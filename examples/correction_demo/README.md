# correction_demo — TraceWin-parity orbit correction

End-to-end demo of HELIX's orbit-correction driver, exercising the
`ADJUST_STEERER` card path that mirrors TraceWin's correction
semantics.

## Files

- `correction_demo.dat` — 6-cell FODO at 5 MeV proton with four
  paired (`ADJUST_STEERER` + `THIN_STEERING` + `DIAG_POSITION`)
  groups, each with `vmax = 0.02 T·m`.  The steerer sits after the
  cell's focusing quad; its BPM sits directly **after the following
  defocusing quad** — a 250 mm lever arm through a quad.  (A BPM
  only 50 mm of drift downstream of its steerer is ill-conditioned:
  nulling ~1.8 mm there demands a ~35 mrad kick, which kills the
  beam.)
- `run_demo.py` — loads the lattice, plants 0.2 mm RMS quadrupole
  misalignments, tracks once, runs
  `run_correction_from_lattice`, tracks again, plots pre/post BPM
  readings, asserts the residual RMS is below 1 % of the
  pre-correction RMS with `status = converged` and 100 %
  transmission at every BPM.
- `correction_demo.png` — plot generated by `run_demo.py`.

## Run

```
python examples/correction_demo/run_demo.py
```

Expected output: pre-correction RMS BPM ≈ 0.51 mm at 100 %
transmission, post-correction RMS ≈ 0, ratio < 1 %, transmission
100 % at every BPM, `status = converged` (PASS, exit 0).  The
one-to-one and SVD methods agree on this deck.

## What the demo proves

1. The TraceWin `ADJUST_STEERER N vmax first_step` card parses into
   an `AdjustSteerer` instance with the right `diag_n` / `vmax` /
   `first_step`.
2. `DIAG_POSITION` cards round-trip through the parser as
   `Marker(is_bpm=True)` — the orbit-correction driver picks them
   up by the `is_bpm` flag.
3. `run_correction_from_lattice` resolves each `ADJUST_STEERER`'s
   `diag_n` to the N-th BPM in the lattice and pairs it with the
   next `Steerer` after the card.
4. The resulting one-to-one (or SVD when overdetermined)
   correction zeros the per-BPM centroid in-place on the lattice —
   each pair nulls its own cell's share of the misalignment orbit.
5. `vmax` from the card is honoured as a per-steerer `T·m` clip on
   `Steerer.bx_l` / `Steerer.by_l`.

## What the demo refuses

The script exits 1 — printing `beam lost at <element>` — whenever
the driver reports `status = "beam_lost"` or any BPM's transmission
is below 100 %.  A corrector that "converges" by scraping the beam
to zero transmission (every downstream BPM then reads exactly 0) is
precisely the failure mode HELIX now detects: the residual RMS
becomes NaN, no convergence is claimed, and the GUI applies no
kicks.  See the dead-beam contract in
`docs/manual/08_errors/07_correction.md`.

For the broader workflow (Monte-Carlo error studies with the
correction step enabled per seed) see
`docs/manual/08_errors/07_correction.md`.
