# HELIX 1.22.0 — bends given as field maps

Released 2026-10-28.  Bends given as 3-D field maps: TraceWin's
`SUPERPOSE_MAP_OUT` clusters, a dipole map bending the reference by any
angle, in multiparticle, envelope and matrix runs.

## Bends given as field maps (new)

TraceWin's `SUPERPOSE_MAP_OUT` is modelled: a dipole given as a 3-D magnetic
field map, alone or with other maps around it, bends the reference
trajectory by any angle.  The reference particle is traced through the
summed fields to the card's exit plane; the element's length is that path;
the beam is pushed along it in the planes normal to it, with the exact
equations of motion; at the exit the beam is moved into the card's frame,
and a card that does not match the traced reference leaves the beam offset,
as in TraceWin.  Every `SUPERPOSE_MAP` operand (X, Y and the three angles)
places its map in such a cluster.  Multiparticle runs (with space charge),
envelope runs (matrix solver) and matrix runs; a compiled push equal to the
numpy code bit for bit; the floor plan draws the bend; the deck writer keeps
the cards.  Backtracking, the Sacherer envelope solver, the torch matrix
path, ring mode and MAD-X export do not take these clusters and say so.
Static magnetic 3-D maps only.  Decks with `SUPERPOSE_MAP_OUT` change: they
parsed with a warning and tracked the maps on a straight axis (the bent
beam was lost); no other deck changes.

## Changes outside it

These can change existing results; each is listed with what it affects.

* **Rows inside field maps** (multiparticle runs with `record_substeps`):
  one row every integration step over the whole map.  They were written
  only during the second half of each space-charge interval, which left a
  gap of half an interval (10 mm at 50 kicks/m) before every run of rows.
  Same number of rows, the beam unchanged (with `periodic_phase` on the fold
  also runs at the new rows: differences in the last bits); the
  time-domain RFQ's rows moved with them, so they still sit on rows of the
  per-cell model.
