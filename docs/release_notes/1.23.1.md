# HELIX 1.23.1 — VaneRFQ retired

Made on 2026-10-31 and not published on its own: its change is released
in 1.24.0.  It retires an element that no deck or project used.  Tracking
results do not change.

## Retired

* **`VaneRFQ`, and the Lattice tab's "RfqCell → VaneRFQ" button.**  The
  whole-RFQ element the button made from a `.vane` file does not
  reproduce an RFQ: its multiparticle push never advances the particle
  phase (no phase slip), and its envelope matrix holds the entry velocity
  with no energy gain.  On a 4.4 m RFQ to 2.1 MeV it transmitted 57 %
  where the RFQ_CELL chain transmits 100 %.  The button is gone;
  constructing a `VaneRFQ` in a script still works but emits a
  `VaneRFQRetiredWarning`.  No deck or project is affected: the parser
  never made one, and saving a lattice that held one wrote the RFQ cells
  back.  RFQs are tracked as RfqCell chains: multiparticle runs use the
  time-domain solver by default, which takes the vanes from the deck's
  `RFQ_GEOM` `.vane` file (or builds them from the cards); envelope
  runs and backtracking use the per-cell model.  The recorded Lattice tab
  tutorial (episode 3) still shows the button until it is re-recorded.
